# Jev 决策网关

把 Jev 的 Key、地址、模型集中登记在一处，多个插件共用。别的插件只要填
**代理地址 + 协议名** 两项，就能拿到 Jev 的判定结果——换地址、换 Key 时只改网关，
不用挨个插件改配置。

```
┌──────────────┐  POST http://127.0.0.1:8770/jev/systemone   ┌────────────────────┐
│  其他插件     │ ──────────────────────────────────────────► │   Jev 决策网关      │
│ (angel_heart │                                             │  协议翻译 / 重试    │
│  soupai …)   │  ◄────────────────────────────────────────── │  去重缓存 / 余额    │
└──────────────┘         统一回 SystemOne 形状的答案          └──────────┬─────────┘
                                                                          │ 按登记的入口
                                    ┌─────────────────────┬───────────────┼───────────────┐
                                    ▼                     ▼               ▼               ▼
                        https://jevmodel.org      api.typesafe.ai   jevtypesafeai.com   自定义协议
                         /v1/systemone            /v1/systemone     /api/v1/decide     你自己的路径
```

## 为什么

多个插件都要用 Jev 判定时，Key 和地址会散落在每个插件的设置栏里。换一个网关
就要改三四个地方，漏改一个就出故障。网关把这件事收成一处：

- 网关里登记若干 **API 入口**，每个入口有自己的协议名、地址、Key、模型、协议类型。
- 其他插件填 `网关代理地址`（如 `http://127.0.0.1:8770`）和 `请求协议`
  （如 `systemone`），插件侧不用再填 Key、地址、模型、超时。
- 上游协议由**网关按入口配置翻译**：插件统一说 SystemOne，上游讲 OpenAI
  Decisions 的话，网关把请求翻过去、把响应翻回来，插件的解析逻辑一行不用改。

## 安装

把仓库放进 AstrBot 的 `data/plugins/` 目录，或在 WebUI 的插件市场里安装后启用。

依赖：`aiohttp`、`httpx`。

## 配置

### 网关侧（这个插件）

| 配置 | 说明 |
|---|---|
| 启用网关 | 关掉就不监听端口 |
| 监听地址 | 默认 `127.0.0.1`。改成 `0.0.0.0` 会暴露给局域网里的其他程序 |
| 监听端口 | 默认 `8770` |
| 访问令牌 | 非本机来源访问时需要带 `X-Jev-Gateway-Token`；本机来的请求免检 |
| 负载均衡策略 | 同一协议登记多个入口时怎么挑：轮询 / 随机 / 加权 / 最少失败 |
| API 入口 | 可登记多条，见下 |

每个入口是一行模板：

| 字段 | 说明 |
|---|---|
| 入口名称 | 这条入口的标识，方便自己分辨，客户端看不到 |
| 协议类型 | SystemOne / OpenAI Decisions / 自定义。自定义类型不做翻译，原样透传 |
| 接口地址 | 上游网关根地址，如 `https://jevmodel.org` |
| API Key | 上游的 Key。网关会用它替换掉客户端带来的 Authorization |
| 模型名 | 请求体里没带 `model` 时用它 |
| 端点路径 | 留空按协议类型取默认（`/v1/systemone`、`/v1/decisions`） |
| 超时 | 秒 |
| 优先级 | 数字越小越优先。默认 100 |
| 权重 | 仅「加权」策略生效，数字越大分到的请求越多。默认 1 |
| 余额查询地址 | 留空＝不查。填了就按需向这个地址查余额 |
| 余额字段 | 返回 JSON 里取哪个字段，支持 `data.balance` 这种点号路径 |

内置三种模板：**SystemOne**（官方 Jev / TypeSafe）、**OpenAI Decisions**、
**自定义协议**（自己起协议名和端点路径，`jevtypesafeai.com` 那种填
`/api/v1/decide` 就行）。

> 同一种协议类型可以登记多条：客户端按**协议类型**找入口，网关在**最高优先级
> 那一层**里按负载均衡策略挑，挑中的失败（Key 错、没余额、上游 5xx）就换同层的
> 下一个，再不行退到低优先级层。适合多 Key 轮换或主备网关。

### 客户端侧（其他插件）

插件的 Jev 设置里只剩两项：

| 配置 | 说明 |
|---|---|
| 网关代理地址 | 如 `http://127.0.0.1:8770` |
| 请求协议 | 固定三项下拉：SystemOne / OpenAI Decisions / Custom |

Key、模型、超时、接口协议全在网关那边。插件的「启用 Jev 判断」开关和判定阈值
之类的业务参数仍在插件自己的配置里。

## 端点

| 端点 | 说明 |
|---|---|
| `POST /jev/<协议类型>` | 中转到该协议类型登记的入口（`systemone` / `decisions` / `custom`） |
| `POST /v1/systemone` | `systemone` 协议的快捷入口 |
| `POST /v1/decisions` | `decisions` 协议的快捷入口 |
| `GET /jev` | 列出已登记的入口（Key 打码） |
| `GET /jev/balance` | 各入口的余额 |
| `GET /health` | 存活检查 |

客户端请求体统一是 SystemOne 形状：

```json
{
  "state": "交给模型看的上下文",
  "questions": {
    "should_reply": {"type": "noul", "instructions": "Is it worth replying?"}
  }
}
```

未登记的协议类型返回 404，响应体里带已登记的协议类型，方便排查。

## 负载均衡与优先级

同一协议类型登记多个入口时，网关这样选：

1. 按**优先级**分层，只在**数字最小的最高优先级层**里挑，低优先级的先不动。
2. 层内按**负载均衡策略**挑一个：

   | 策略 | 行为 |
   |---|---|
   | 轮询 | 依次轮流用每个入口 |
   | 随机 | 每次随机挑 |
   | 加权 | 按权重分配，权重大的分到的多 |
   | 最少失败 | 成功率高的优先，同时给没被选过的入口一点探索机会 |

3. 挑中的入口失败（401/402/403、上游 5xx、连不上）就换**同层**的下一个，
   同层用完再退到**低优先级**层。
4. 连续失败会把这个入口标记为不健康并暂时跳过，冷却一段时间后放回来重新试。

失败率超过 50% 或者连续失败 3 次的入口会被摘掉。WebUI 的「配置」页能看到每个
入口的优先级与权重，「网关设置」里能改负载均衡策略。

## Docker 部署

容器里的 `127.0.0.1` 指的是**容器自己**——不是宿主机，也不是别的容器。按场景对号入座：

| 场景 | 网关侧设置 | 客户端插件填的地址 |
|---|---|---|
| 插件和网关在同一个容器 | 监听地址 `127.0.0.1`（默认即可） | `http://127.0.0.1:8770` |
| 插件和网关在不同容器 | 监听地址 `0.0.0.0`，对外地址填网关容器名 | `http://<网关容器名>:8770` |
| 插件在宿主机、网关在容器 | 监听地址 `0.0.0.0`，对外地址填宿主机可达地址 | `http://<宿主机IP>:8770` |

**对外地址**就是别的插件该填的那个地址，WebUI 的顶部和 `/jev网关` 指令里都会显示，
照抄就行。网关监听 `127.0.0.1` 却填了对外地址时，网关会在日志里提醒你改成 `0.0.0.0`。

跨容器时建议顺手设一个**访问令牌**：客户端把地址写成
`http://<令牌>@<网关容器名>:8770`，客户端会自动把令牌作为 `X-Jev-Gateway-Token`
头发过去——插件那边仍然只填「网关地址 + 协议名」两项，不用多填。

Docker Compose 片段：

```yaml
services:
  astrbot:
    image: soulter/astrbot
    container_name: astrbot
    ports:
      - "6185:6185"
    volumes:
      - ./data:/AstrBot/data

  another-bot:
    image: soulter/astrbot
    container_name: another-bot
    depends_on:
      - astrbot
    volumes:
      - ./data2:/AstrBot/data
```

这时网关插件装在 `astrbot` 容器里，另一个容器里的插件填
`http://<令牌>@astrbot:8770`；网关的监听地址要改成 `0.0.0.0`。

用 `network_mode: host` 的话容器和宿主机共用网络栈，`127.0.0.1` 仍然可用，
但要留意端口会直接暴露在宿主机上。

连不上时先按这个顺序查：

1. 网关插件启用了吗？`/jev网关` 看状态是不是「运行中」；
2. 监听端口和客户端填的端口一致吗？
3. 跨容器的话，监听地址是不是 `0.0.0.0`、地址里的主机名是不是容器名；
4. 设了令牌的话，客户端地址里有没有带 `令牌@`。

```bash
python scripts/probe_gateway.py --gateway http://<网关容器名>:8770
```

## WebUI

插件带一个可视化页面（AstrBot → 插件 → Jev 决策网关），四个页签：

- **配置**：增删改 API 入口，保存后即时生效。明文 Key 不出后端，列表里只显示打码值；
  留空表示不改原来的 Key。
- **测试**：选一个协议，填 state 和 questions，发一次真实请求看响应与耗时。
- **拓扑**：接入对象 → 网关 → API 入口的关系图，见下。
- **余额**：各入口的余额、来源和更新时间。

余额有两个来源：随响应回来的（官方 Jev 在响应头 `X-Tokens-Remaining`，第三方代理在
响应体 `usage.credits_remaining_usd`），以及入口上配了「余额查询地址」时按需查询的。

### 拓扑图

「拓扑」页签画的是谁在用这个网关：

```
接入对象 ──► 网关 ──► API 入口
```

- **接入对象**是调用过网关的客户端插件。客户端在请求里带一个
  `X-Jev-Gateway-Client: <插件名>` 头自报家门，网关记下谁来过、来了几次、走的哪个协议。
  没带这个头的客户端不会出现在图里。
- **网关**节点显示监听地址、端口与对外地址。
- **API 入口**节点显示协议类型、优先级、权重与成败统计；入口被熔断时变红。
- 接入对象最近五分钟没再调用会变灰。

点节点会在图下方展开详情，**配置直接嵌在详情里**，不用跳去别的页签：

- 点**网关**节点 → 监听地址、端口、对外地址、负载均衡策略、访问令牌都能就地改
- 点**API 入口**节点 → 入口名称、协议类型、地址、Key、模型、端点路径、超时、
  优先级、权重都能就地改，改完点「保存这个入口」
- 点**接入对象**节点 → 只看得到调用情况（客户端插件本身不用配）

图可以拖拽节点、滚轮缩放。渲染引擎参考
[astrbot_plugin_livingmemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory)
的 canvas 图谱（力导向布局 + 曲线边 + 粒子流动），按本图规模做了收敛。

## 中间处理

请求进网关到响应回客户端之间，可以插入自定义处理。默认只做两件事：请求体
没带 `model` 时补上入口配置的模型；日志里不出现明文 Key。

要加自己的逻辑，在插件目录下放一个 `hooks_ext.py`：

```python
async def before_forward(entry, ctx):
    """ctx = {"method", "path", "headers", "body", "internal"}；返回 dict 覆盖字段。"""
    return None


async def after_response(entry, ctx):
    """ctx = {"status", "headers", "body"}；返回 dict 覆盖字段。"""
    return None
```

返回 `None` 表示不干预。改完在 WebUI 里重载插件即可生效。

## 排查

```bash
python scripts/probe_gateway.py --gateway http://127.0.0.1:8770
```

会依次检查网关是否在跑、登记了哪些入口，并通过指定协议发一次真实请求。
